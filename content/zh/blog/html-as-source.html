界面经常存在于多个地方：设计稿描述外观，组件代码组织结构，业务代码保存数据与操作。当这些来源分别变化时，保持一致就变成额外的工作。

nanshann 选择 HTML 作为共同编辑来源。页面直接声明组件引用、公开输入与业务事件；组件定义维护内部结构、样式和局部交互。Agent 与未来的设计工具面对同一份内容。

让依赖出现在使用位置

一段清晰的 HTML 不只是“可读源码”。它还需要说明显示的数据来自哪里，交互触发哪个动作，组件对外开放什么输入。明确这些关系，才能让修改具有边界，也让验证有对象。

共同来源的价值，在于让结构与关联持续可追溯。

仅仅采用 HTML 并不自动证明 Agent 友好。状态、动作、依赖和资源所有权仍需要明确契约；长期效率也需要固定任务上的测量。

共享定义与页面配置

页面搭建引用已有组件，调整排列、公开配置和业务绑定。内部 HTML、CSS 和 Behavior 的修改属于组件开发，直接维护共享定义。更新兼容的视觉实现时，已有业务关联应该继续有效。

这个边界避免通过展开组件源码、复制进每个页面来完成布局。组件资产保持关联，每个实例仍拥有自己的局部状态和资源。

创作工具是协作者

未来的页面画布与组件编辑器可以编辑同一套文件，分别承担页面搭建与组件开发。应用运行不以它们为前提，也不依赖额外的设计转码结果。

可视化编辑器和能力发现工具目前尚未实现。HTML 组件与绑定协议已经可以独立用于代码开发。
