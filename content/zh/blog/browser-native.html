“应用无需构建”描述的是运行方式：浏览器加载 HTML、CSS 和 JavaScript ES Module，框架在浏览器中解析组件模板并建立绑定。

这不意味着框架仓库没有开发工具。nanshann 使用 TypeScript 开发，发行构建生成浏览器 ESM 和类型声明。使用端拿到发行文件后，可以直接编写浏览器能够执行的应用。

从两个文件开始

入口 index.html 声明 import map，加载 nanshann，再用 ns-include 引用 counter.html。组件文件包含结构、样式和顶层 Behavior。状态变化通过绑定更新已有 DOM。

这种组织方式让文件来源与运行位置容易追踪。应用可以使用普通静态服务器，框架发行与页面创作保持独立。

保留浏览器的边界

原生运行仍需尊重 URL、模块与 CSS 的规则。外部模块的相对导入按模块文件地址解析；内联 Behavior 使用 Blob ESM，依赖通过 import map 名称或完整 URL 引入。

CSS 由浏览器解析。需要相对资源时使用外部样式表，让 url() 相对 CSS 文件解析。Shadow DOM 提供样式边界，不是安全沙箱。

把部署作为可验证的步骤

完整部署发行目录，检查 MIME 与资源 404，再在实际 CSP 下验证。History 路由需要文档回退；多页站点直接提供对应 HTML。

浏览器直接运行是使用契约，不是性能排名。包体积、长期内存和 Agent 效率需要在明确环境与方法下单独测量。
