Choose History routing or standard multi-page navigation to suit your application. This website keeps its shell in a root ns-route and switches content through relative child routes. Public URLs retain HTML entry documents for direct visits and refreshes.

History routing

<ns-route path="/orders" src="./orders.html"></ns-route>
<ns-route index src="./not-found.html"></ns-route>

ns-route loads a component only when matched. Top-level paths are absolute; nested paths are relative. Static segments and single-segment :id parameters are supported. index is a fallback when no other candidate matches and does not rewrite the URL.

import { navigate } from 'nanshann';
navigate('/orders/42?tab=items');
navigate('/orders', { replace: true });

Ordinary same-origin links participate in History navigation. Parameter changes recreate affected route components; search/hash-only changes preserve local instances. ctx.route exposes reactive pathname, params, search and hash.

Native multi-page navigation

<a href="/docs/" target="_self">Documentation</a>

Links with target preserve native browser behavior. A multi-page application can explicitly use target="_self" to load another document without same-origin navigation being intercepted.

Server configuration

History applications need a document fallback or explicit HTML entries that boot the same application for deep links, while missing JS, CSS and component HTML must return 404. Multi-page sites serve the corresponding HTML directly and need no History fallback.
