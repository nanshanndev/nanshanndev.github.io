createState manages objects and arrays through ordinary property access. Signal handles individual values and derived computations. Both use the same reactive mechanism.

Create and update state

import { createState, Signal, batch } from 'nanshann';
const state = createState({ price: 100, quantity: 2 });
const total = new Signal.Computed(() => state.price * state.quantity);
const stop = total.subscribe(value => console.log(value));

batch(() => {
  state.price = 80;
  state.quantity = 3;
});
stop();

Reads establish dependencies; writes notify affected subscribers. batch groups synchronous updates. A subscription immediately receives the current value and returns a cleanup function.

Values and computations

const count = new Signal.State(0);
const doubled = new Signal.Computed(() => count.get() * 2);
count.update(value => value + 1);
doubled.get(); // 2

Computed is lazy, cached and read-only. Its function should be synchronous and free of side effects. Signal uses Object.is: replace an object reference to express a change, or use createState for deep field updates.

Ownership and templates

Create local state inside the Behavior function for each instance. Complex property inputs retain the caller’s reference and should be consumed without mutation.

Templates do not automatically unwrap a Signal stored in state. A getter on an ordinary state object can call .get() so the binding tracks it:

return {
  state: { get count() { return count.get(); } },
  actions: { increment() { count.set(count.get() + 1); } }
};
Use ctx.subscribe inside Behavior for managed cleanup. Direct subscribe calls remain the caller’s responsibility; removing DOM does not release an unmanaged subscription.
